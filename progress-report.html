TIAS 航空看板 — 開發進度報告

專案：交通助理 (thsr-bot) ／ 報告日期：2026-05-19 ／ 負責人：Wengtangyong
目前狀態：功能暫停開發
所有可行的資料取得方案均已驗證失敗，缺少登機門 / 報到櫃台 / 行李轉盤欄位，功能不值得繼續。TIAS 看板入口保留於首頁，/tias 頁面維持空資料展示。

一、目標

在 Railway 部署的 Flask App 上顯示桃園機場 AirAsia 集團航班即時動態，包含：

  • 入離港時刻（表訂 / 預計）
  • 登機門、報到櫃台、行李轉盤
  • 航班狀態（延誤 / 登機中 / 已降落…）

二、嘗試方案彙整

方案 方法 結果 失敗原因
直接 API 呼叫 requests.get() 打機場內部 API 封鎖 Cloudflare Managed Challenge（需 JS proof-of-work）
Playwright headless Chromium headless 模擬瀏覽器 封鎖 TLS 指紋 (OpenSSL vs BoringSSL)、自動化特徵偵測
curl_cffi 模擬 Chrome TLS impersonate="chrome124" 封鎖 TLS 通過，但 JS PoW challenge 仍需真實瀏覽器執行
真實 Chrome（非 headless） channel='chrome' 有 GPU 視窗模式 封鎖 取得 cf_clearance + TS011b5520 cookie，但 API 仍回 403（F5 BigIP WAF 第二層）
頁面內 fetch（page.evaluate） 在已通過 WAF 的頁面 JS 環境發 XHR 封鎖 API endpoint 有獨立 WAF 規則，同樣 403
機場 Open Data CSV odp.taoyuan-airport.com CSV 下載 資料過舊 1,000 筆資料全部日期為 2023-08-17（靜態快照，非即時）
GitHub Gist 中繼架構 Mac（台灣 IP）抓 CSV → 上傳 Gist → Railway 讀 方案廢棄 底層 CSV 是靜態資料，中繼架構無意義
第三方 API（AeroDataBox 等） 商業航班資訊 API 資料不足 有時刻表，但無登機門 / 報到櫃台 / 行李轉盤欄位

三、根本原因

桃園機場網站有雙層 WAF：

  • Cloudflare Managed Challenge：需要真實瀏覽器執行 JS PoW（5 秒盾）
  • F5 BigIP WAF（TS Session Cookie）：API 端點有獨立規則，即使持有合法 cf_clearance 仍拒絕非瀏覽器發出的 API 請求

兩者同時存在，任何自動化方案在 Railway 雲端伺服器上均無法突破。

四、唯一未驗證的方向

方向 說明 可行性
機場內部 Wi-Fi 從桃園機場內網發 API 請求，WAF 規則可能僅針對外部流量 未知（需實地測試）

測試方式：連接機場 Wi-Fi，執行 curl https://www.taoyuan-airport.com/api/api/flight/a_flight?...，觀察是否繞過 Cloudflare。
